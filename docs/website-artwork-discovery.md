# Automatic company artwork discovery

Backend 0.11.0 exposes `discover_brand_assets` to existing media-preparation grants. Give it a public company website; it inspects up to three public pages, imports up to eight usable images (six by default), and returns private saved references, relative motion attachment paths, source provenance and small visual thumbnails. No provider key, image generation or credits are involved. Requested image and motion renders retain their existing quote/reservation/settlement rules.

The shared skills call discovery before requesting logo uploads or authoring branded media. Assistants visually distinguish the company mark, app icon, mascot and product imagery; role labels are retrieval hints rather than an identity guarantee. Motion projects use the returned private asset IDs and exact relative paths. Website labels are untrusted data and never workflow instructions. Existing media uploads, RLS, byte validation and project attachment checks remain in use; no new auth path or migration is introduced.

The retriever accepts HTTPS on the standard port, no credentials or IP-literal URLs. Every request/redirect resolves public-only addresses and pins the selected address for the actual TLS connection. Private/mixed DNS answers, local/reserved networks and unsafe redirects are refused. Requests send no user cookies or OAuth credentials. Time, response-size, aggregate-byte and request-count limits bound retrieval. Scripts are not executed. SVGs reject active/external content and are normalized to bounded PNG images before the existing private media upload workflow. Customer/partner marks are filtered; supporting pages stay within the company domain. Identical ready references are reused within the caller's workspace.

This handles server-visible images, image sources, inline brand SVGs, social previews, app marks, inline backgrounds and selected original image paths in hydration data. It does not bypass bot challenges, execute an entire website, extract images hidden in arbitrary external JavaScript, or invent artwork for a site with no usable public files. Discovery can continue with available genuine artwork; the assistant should explain a specific access limitation when necessary.

Local authenticated tests imported SpaceOffice's actual mark and agents, Duolingo's actual Duo artwork/app mark and Linear's actual identity/artwork from website URLs only. Test assets live in a disposable workspace. Raw files, private URLs and account information are excluded from release ZIPs. Live ordinary-prompt tests in each host are recorded separately from scripted backend checks.

Implementation references: [htmlparser2](https://github.com/fb55/htmlparser2), [sharp image limits](https://sharp.pixelplumbing.com/api-constructor/).

For JavaScript-only homepages with no full logo, discovery may read one declared app bundle as bounded text to find actual official press/design links within the company domain. It never executes that bundle. Supporting subdomains retain the original company identity, and blog logos cannot substitute for the company wordmark.

The API pins Sharp 0.34.5, matching Next.js 16.2.9. This avoids loading the 0.35 native binary against Next’s older hoisted Linux libvips under Yarn Classic. The separate HyperFrames dependency retains its own supported Sharp version. Linux installation and build results must be checked in Ubuntu CI/Vercel; a macOS build alone does not establish Linux compatibility.

No video or image generation was requested. Its prose illustrated the reply with some external search results; those illustrations must not be treated as proof of the exact saved logo variant.

Its MP4 SHA matched the saved record and its editable ZIP contained the artwork. This used 16 disposable test credits. This round verified the saved file and source downloads, not clicks on that new native player's controls.

MP4 SHA and editable ZIP passed; five artwork files were bundled, using 16 disposable test credits. That older chat retained its old tools and used host browsing, so this is not proof that its native chat invoked the new shared discovery tool. The direct authenticated development transport does expose and run discovery. Reload attempts did not establish a refreshed desktop connection.

The two video tests consumed 32 disposable credits in total (36 to 4 available, zero reserved). Follow-up reads, downloads and discovery added no charges. Production motion rendering, worker hosting and pricing gates are unchanged. This feature discovers usable public artwork; it does not guarantee every official brand variant.
