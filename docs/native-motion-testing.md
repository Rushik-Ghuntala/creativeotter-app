## Duplicate video cards — 7 November 2026

The old motion workflow polled `get_render`, an MCP App tool. Each assistant-side poll opened another player, and a raw video embed in the final answer could add one more. This was repeated presentation of the same saved render, not separate render jobs.

`get_render_status` now reads the existing workspace-scoped job without a UI template, signed media URLs, storage signing or a new preview credential. `render_design` opens the initial auto-updating player; `get_render` remains compatible for explicit saved-video viewing and widget refresh. Updated skills use status-only polling and a brief final reply referring to that player, without a raw MP4 embed or a published local source-preview card. No billing, rendering, database migration or permission changes are included.
